# Amchi Konkani ASR — Next Experiments Guide

**For the RunPod agent. Read this file before doing anything else for Amchi Konkani training.**

Last analysis date: 2026-03-07
Previous run: 50-epoch full fine-tune → Test WER **54.7%** (3 speakers, Story 5)
Pilot reference: 20-epoch full fine-tune → **35.1%** (1 speaker, Story 5, val=test same file — optimistic)

---

## What we learned from the 50-epoch run

1. **Overfitting is the primary problem.** All 115M encoder parameters were updated on only
   511 training samples. CTC val_loss doubled (49 → 92) between epochs 6 and 49. Even for
   the dominant training speaker (ashaheble, 156 train samples), WER regressed from 35.1%
   (pilot) to 51.7% — confirmed by a statistically significant Wilcoxon test (p=0.00043) on
   38 matched samples.

2. **Speaker imbalance made it worse.** dipti.ajgaonkar21 had only 3 training samples but
   35 test samples → WER 60.3%, vs ashaheble 51.7% and lalimomadi 51.9%.

3. **The dev set never saw dipti.** The ModelCheckpoint selected checkpoints based on
   Story 4 (dev), which had zero dipti samples. So the best checkpoint was never optimised
   for dipti's voice.

4. **RNNT does NOT corrupt the encoder.** The training_step is monkey-patched to CTC-only.
   RNNT decoder and joint are never called. Overfitting is purely from CTC-path encoder
   training on too little data.

---

## Two experiments to run

### Experiment 1 — Run C: Freeze Encoder (story-based split, existing data)

**Hypothesis:** The Marathi encoder already captures acoustics close enough to Konkani.
Only the CTC output head (~132K params) needs to adapt. Freezing the 115M-param encoder
eliminates overfitting.

- Config: `configs/amchi_konkani_run_c.yaml` (already committed — use as-is)
- Data split: unchanged (Stories 1,2,3,7 → train; Story 4 → dev; Story 5 → test)
- Key settings vs 50-epoch run:
  - `freeze_encoder: true` → 132K trainable params instead of 115M
  - Cosine LR with 500-step warmup (was flat 0.0001)
  - `weight_decay: 0.01` (was 0.001)
  - `max_epochs: 100` (model was still improving at epoch 47)

**Expected:** WER below 50% on Story 5. Dipti will still be underrepresented (same split).

---

### Experiment 2 — Run S: Speaker-Stratified Split + Freeze Encoder

**Hypothesis:** dipti's high WER (60.3%) is caused by near-zero training representation
(3 train samples). A stratified split gives dipti ~26 training samples and ensures all
3 test speakers appear in dev (so ModelCheckpoint can account for them).

- Config: `configs/amchi_konkani_run_c_stratified.yaml` (see below)
- Data split: **generated by `scripts/create_speaker_stratified_split.py`**
  - Reads the existing story-based manifests (after data download)
  - Re-splits each speaker's recordings 70% train / 15% dev / 15% test
  - Writes to `data/amchi_stratified/{train,dev,test}/manifest.jsonl`
  - Audio files are NOT moved — manifests reference original paths
- Same freeze settings as Experiment 1

**Note on text overlap:** Because dipti only recorded Story 5 content, some Story 5
sentences will appear in training (spoken by dipti) and also in test (spoken by
ashaheble or lalimomadi). This is acceptable for CTC ASR — the model learns
audio→token mappings, not text statistics. Different speakers produce completely
different spectrograms for the same sentence.

**Expected split statistics (approximate):**
```
ashaheble    (211 total): ~148 train /  32 dev /  31 test
lalimomadi   (197 total): ~138 train /  30 dev /  29 test
dipti        ( 38 total):  ~27 train /   6 dev /   5 test   ← was 3/0/35
avkulkarni   (125 total): all train (~125)
arursushama  ( 43 total): all train (~43)
sheela.kalawar(41 total): all train (~41)
milindkopi   ( 15 total): all train (~15)
mokshkopi    (  3 total): all train (~3)
─────────────────────────────────────────────────────
Train total: ~504  Dev total: ~68  Test total: ~65
```
(Exact numbers depend on random seed; script uses seed=42 for reproducibility.)

**What this tests vs Experiment 1:**
- Experiment 1: Can freezing the encoder fix overfitting? (same hard split)
- Experiment 2: Does dipti's WER improve with ~27 train samples vs 3? (easier split,
  test text overlaps with training via other speakers)

## Full RunPod setup (do this once before either experiment)

### 1. Clone repo and pull latest

```bash
cd /workspace
git clone https://github.com/milind-kopikar/amchi_asr.git
cd amchi_asr
git pull origin master
```

### 2. Set up environment variables

```bash
cp .env.example .env
# Edit .env and fill in:
#   HF_TOKEN=hf_...           (for AI4Bharat model download from HuggingFace)
#   GITHUB_PAT=ghp_...        (for git push of results)
#   GEMINI_API_KEY=AIzaSy...  (optional, only needed for post-processing)
source .env
```

### 3. Install NeMo and fix cu128 PyTorch

**Do these in order — the force-reinstall step is mandatory on every fresh pod.**

```bash
pip cache purge                            # frees ~8GB on root filesystem
pip install "nemo_toolkit[asr]" --ignore-installed blinker -q
pip install --force-reinstall torch torchvision torchaudio \
    --index-url https://download.pytorch.org/whl/cu128 -q
```

Verify GPU is visible:
```bash
python3 -c "import torch; print(torch.cuda.is_available(), torch.cuda.get_device_name(0))"
```
Must print `True` and a GPU name. If not, stop and diagnose before proceeding.

### 4. Apply the conv_asr patch (required after every NeMo install)

```bash
NEMO_FILE=$(python3 -c "import nemo.collections.asr.modules.conv_asr as m; print(m.__file__)" 2>/dev/null | tail -1)
cp patches/conv_asr_fixed.py "$NEMO_FILE"
echo "Patch applied to: $NEMO_FILE"
```

### 5. Download the AI4Bharat Marathi base model

```bash
source .env
huggingface-cli login --token "$HF_TOKEN"
python3 scripts/download_model_from_hf.py   # downloads to models/
```

Expected result:
`models/indicconformer_stt_mr_hybrid_ctc_rnnt_large/indicconformer_stt_mr_hybrid_rnnt_large.nemo`
(~500MB)

### 6. Download Amchi Konkani audio data

```bash
python3 scripts/download_data_from_railway.py \
  --base_url https://konkanicollector-production.up.railway.app \
  --output_dir data/amchi \
  --use_story_split
```

This downloads audio into `data/amchi/{train,dev,test}/audio/` and uses the
existing manifests already in the repo (`data/amchi/{train,dev,test}/manifest.jsonl`).

Verify:
```bash
wc -l data/amchi/train/manifest.jsonl   # expect 511
wc -l data/amchi/dev/manifest.jsonl     # expect 58
wc -l data/amchi/test/manifest.jsonl    # expect 104
ls data/amchi/train/audio/ | wc -l      # expect 511
```

## Running Experiment 1 — Run C (Freeze Encoder, story-based split)

```bash
cd /workspace/amchi_asr
export APPLY_CONV_PATCH=1
python3 scripts/fine_tune.py --config configs/amchi_konkani_run_c.yaml
```

Training runs for up to 100 epochs. ModelCheckpoint saves to
`/workspace/nemo_experiments/amchi_konkani_run_c_frozen_cosine_100ep/`.

**Monitor progress:**
```bash
# Watch val_loss and val_wer in real time
tail -f /workspace/nemo_experiments/amchi_konkani_run_c_frozen_cosine_100ep/*/logs/*.log 2>/dev/null || \
  watch -n 30 "ls -t /workspace/nemo_experiments/amchi_konkani_run_c_frozen_cosine_100ep/checkpoints/*.ckpt 2>/dev/null | head -5"
```

**When training finishes, evaluate:**
```bash
BEST_CKPT=$(ls -t /workspace/nemo_experiments/amchi_konkani_run_c_frozen_cosine_100ep/checkpoints/*.ckpt 2>/dev/null | grep -v last | head -1)

python3 scripts/evaluate.py \
  --checkpoint "$BEST_CKPT" \
  --manifest data/amchi/test/manifest.jsonl \
  --output results/experiments/run_c_story_split/final_test_results.json
```

## Expected outcomes and what to watch for

| Metric | 50-epoch baseline | Run C target | Run S target |
|--------|-------------------|-------------|-------------|
| Overall WER | 54.7% | < 50% | < 50% |
| ashaheble WER | 51.7% | < 45% | < 45% |
| dipti WER | 60.3% | ~58% (unchanged train) | < 50% (27 train) |
| lalimomadi WER | 51.9% | < 45% | < 45% |
| Val loss trend | 1.86× increase | Should plateau or decrease | Should plateau |

If Run C WER is **higher** than 54.7%: the frozen encoder is not adapting enough.
Consider partial freeze (top 6 of 18 ConformerLayers) as a follow-up.

If Run S dipti WER does not improve vs Run C: speaker representation was not the
bottleneck; collecting genuinely new dipti recordings for earlier stories is needed.

## Troubleshooting

| Symptom | Fix |
|---------|-----|
| `RuntimeError: operator torchvision::nms does not exist` | Re-run the force-reinstall torch step (§3) |
| `OSError: Could not load libtorchaudio.so` | Same fix |
| `CUDA out of memory` | Reduce `batch_size` from 4 to 2 in config |
| `val_wer` stuck at 1.0 for first 5 epochs | Normal — CTC decoder starts from random init |
| Checkpoint dir not found for evaluate.py | Check exp_dir in config matches actual path |
| `ModuleNotFoundError: nemo` | NeMo install failed; re-run pip install step |

See also: `LEARNINGS.md` §5–7, `MASTER_REPRODUCTION_GUIDE.md`.
